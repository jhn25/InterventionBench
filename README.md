# InterventionBench

**Can LLM Agents Adapt to Mid-task User Interventions?**
*Findings of EMNLP 2026*

Real users do not state a goal once and walk away. They revise it while the agent is working: swap a target, add a request, drop a step, or cancel everything. **InterventionBench** measures how well LLM agents adapt when the goal changes mid-task, on top of two stateful long-horizon environments: [AppWorld](https://github.com/StonyBrookNLP/appworld) and [WebArena](https://github.com/web-arena-x/webarena).

## How it works

Every instance pairs an original task **τ_A** with a revised task **τ_B** and is evaluated in three scenarios:

| Scenario | What the agent gets | What it measures |
|---|---|---|
| **A** | τ_A from the start | base capability |
| **B** | τ_B from the start | difficulty of the revised task alone |
| **A→B** | τ_A first, then the intervention arrives mid-task | adaptation |

**Adaptability** = success in A→B among the instances the agent can solve standalone in B, so a hard revised task is never counted against the agent.

## Intervention taxonomy

Each intervention modifies the task's **verb** (the action), **target** (the entity), or **both**, by one of three operations:

| | Verb | Target | Both |
|---|---|---|---|
| **Swap** | replace the action | replace the entity | replace the whole sub-task |
| **Add** | add an action | add an entity | add a whole sub-task |
| **Drop** | remove an action | remove an entity | cancel everything (*Cancel*) |

**2,250 intervention instances** built from **272 base tasks** (1,088 AppWorld + 1,162 WebArena), generated by an LLM pipeline and verified by a human audit (97.2% type correctness) plus execution-based evaluator screening.

## Key results (12 models, closed + open-weight)

- **Adaptability is low everywhere.** The strongest model preserves only 71% of the interventions it can solve standalone on AppWorld; most models fall below half.
- **Agents can replace a goal, but cannot take on another one.** Swap and Drop reach roughly 80% and 78%, while **Add collapses to 20%** (AppWorld, pooled).
- **The added goal is not the problem. The original goal is.** About three quarters of Add failures complete the added goal but fail to preserve the original one, and the agent usually ends by declaring both tasks complete.
- **This is neither forgetting nor a step limit.** The agent still refers to the original goal in ~93% of failing runs, rarely exhausts its budget, and stops on its own.
- **Existing planning and memory frameworks do not close the gap.** Eight wrappers (Reflexion, AdaPlanner, Mem0, HippoRAG, ...) help on Swap/Drop but leave the Add gap in place.

## Quick start

```bash
pip install -r requirements.txt

# Recompute all scores from the released data
APPWORLD_ROOT=/path/to/appworld python scripts/score_add_assertions.py
python scripts/eval.py --results results/

# Run new inference (environments installed per their upstream repos)
python scripts/run.py --domain {aw|wa} --condition {A|B|A_to_B} --workers N
```

Scoring: Swap and Drop require the revised-task evaluator to pass and the original-task evaluator to fail. Add requires both tasks to be satisfied; on AppWorld this is checked at the assertion level on the final state, excluding only cross-task no-other-change assertions. Cancel uses a trajectory-level stopping rule.

## Layout

- `data/` — intervention instances (JSONL, one row per instance; screened rows keep explicit `skip` flags) + `CHANGELOG.md`
- `src/interventionbench/` — runner, workers, and baseline framework wrappers
- `scripts/` — `run.py` (inference), `score_add_assertions.py` (assertion-level Add scoring), `eval.py` (aggregate metrics)
- `results/` — released trajectories and aggregated metrics

## Dataset version

Current: **v1.1** (camera-ready). Evaluator repairs, strengthened WebArena checks, and four excluded instances; every change is indexed in `data/CHANGELOG.md`. Known limitation: 44 BothAdd intervention texts contain a residual phrasing conflict (`data/known_limitations.json`) and will be revised in v1.2.
